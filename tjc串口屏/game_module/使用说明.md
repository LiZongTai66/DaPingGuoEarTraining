# 钢琴音游模块：小星星完整版

代码已经生成并完成本地检查。**当前版本适配 `tm0.tim` 最小 50 ms 的屏幕，仅使用现有 `t0`、`n0`、`n1` 显示，不需要 `t1`、`t2` 或字符串变量 `tmp`。**与上一版 50 ms 模块相比，FPGA 源码和串口协议相同，只需要更新屏端 `01`、`02`、`03` 三个事件；`04`、`05` 保持相同。如果仍在使用最初的 20 ms 版本，则须使用包内的 50 ms FPGA 源码。**`piano.HMI` 尚未改写**：请在淘晶驰编辑器中按下表添加变量、粘贴事件，再编译下载。没有生成 `.tft` 或 FPGA 比特流，也没有连接实际屏幕与开发板做上板测试。

## 1. 屏幕组件与属性

工程里实际定时器名称是 **`tm0`**，不是 `tim0`。在 `game` 页面检查下列组件；存在的直接复用，不存在的添加。以下程序使用这些固定名称。

| 名称 | 类型 | 属性 / 作用 |
|---|---|---|
| `tm0` | 定时器 | `tim=50`，`en=0`；替换定时事件 |
| `m0` | 触摸区域 / 返回按钮 | 返回主页；替换触摸弹起事件 |
| `m1` | 触摸区域 / 开始按钮 | 开始 / 重新开始；替换触摸弹起事件 |
| `t0` | 文本 | 歌名，沿用中文字体 |
| `n0` | 数字 | 分数，至少能显示 4200；建议 `lenth=4` |
| `n1` | 数字 | 当前连击，至少能显示 42；建议 `lenth=2` |
| `va0`～`va14` | 数值变量 | `sta` 设数值，初值 0；已有的复用，其余新增 |
| `rx` | 新增数值变量 | **`vscope=全局`**，初值 0；FPGA 写入的累积状态 |
| `snap` | 新增数值变量 | 收到状态的本次副本，初值 0 |
| `miss` | 新增数值变量 | 漏键 / 错键合计，初值 0 |
| `pos` | 新增数值变量 | 绘图坐标临时值，初值 0 |
| `kind` | 新增数值变量 | 结束标记临时值，初值 0 |

屏幕保留原布局：`t0` 始终显示歌名，`n0` 显示分数，`n1` 显示连击。新增数值变量不占显示区域，不需要为提示文字腾空间；不要把普通控件叠在下落轨道上。

绘图沿用提取到的原游戏逻辑：背景图片 **18**，音符图片 **19**，音符大小 **50×14**。七轨横坐标是 **57、110、163、216、269、322、375**；出生 y=28，判定 y=180，绘图区约为 x=57..424 / y=28..193。**请在编辑器中确认图片 18 与 19 的编号、大小、背景区域相符**。这是从现有事件代码得到的布局假设，尚未经屏幕渲染验证；若实际当前页面用了另一张背景，应把事件中的 `xpic ...,18` 统一改成当前背景图片编号。

`va0..3` 是四个音符槽的年龄；`va4` 是曲谱时钟；`va5..8` 是对应轨道 x；`va9` 是状态（0 待机 / 1 演奏 / 2 等结算 / 3 完成 / 4 回传超时）；`va10` 是结算超时；`va11..14` 是对应音高。旧 `tm1` 及其他会改写这些变量、发 D/F 指令或绘图的游戏事件应停用，避免重复运行。

跨页面串口赋值要求目标变量为全局，这是淘晶驰官方说明中的要求：
[淘晶驰：跨页面操作变量](https://www.tjc1688.com/contents/25/465.html)。因此 `rx` 的全局属性不能漏。

## 3. FPGA 修改

将原 Verilog 源文件的内容替换为 **`piano_game_complete.v`**，然后在高云 IDE 重新综合、布局布线、下载。顶层模块仍叫 `ads1115_pressure_test`，端口保持相同，沿用原 CST；不要同时保留两份同名顶层模块。

这是**单文件完整源码**，文件末尾已经包含 `rhythm_game_core` 和 `rhythm_game_tx`。目录里单独的 `rhythm_game_core.v` 是便于阅读和单元测试的版本；使用完整文件时不要再把它加入综合源列表，否则会重复定义模块。

硬件仍为 27 MHz / UART 9600 8N1。屏幕 TX→FPGA RX；FPGA TX（原注释为 N8，以实际 CST 为准）→屏幕 RX；共地。七键实际由 ADC1 四通道、ADC2 三通道构成；原注释中的“6 keys”已过时，本次依据真正的七键信号处理。

主要改动：

- 新增真实按键判定和状态回传，正确命中才触发音游发声。
- 保留自由演奏及示范模式的触发路径；主页和结束后不再由裸按键触发发声。已经启动的原声部包络会正常衰减，不做瞬时硬切音。
- 为 `F0` 补上真正的结束处理，关闭游戏模式及 LED。
- 自由演奏图片指令与游戏状态共用一个 UART 发送器，按**完整指令**仲裁，连同三个 FF 结束符一起发送，防止指令交错。
- 计数在 FPGA 累积；一次发送取同一个快照；屏幕先复制到 `snap` 再拆字段，避免读到一半时串口更新。

没有修改 ADC 采集、压力阈值、音色生成及 PT8211 接口算法。

## 4. 游戏规则与时序

小星星完整 A-B-A，42 音符 / 48 拍，每拍 400 ms，开始有 3 秒准备时间（不显示倒计时文字）；首个音符在 3.8 秒到判定线。整局屏端约 23.2 秒，再等待最终回传。

- 屏幕每 50 ms 移动 10 像素，y 超过 180 时截到 180；音符到达判定线后短暂停留，直到晚判定窗口结束。启动代码会设置 `tm0.tim=50`，不能只修改属性而继续沿用旧计数。
- 槽年龄达到 14（出生后 650 ms、y=158）发出目标 `D0..D6`，FPGA 从收到目标起开放 300 ms 窗口；槽年龄 17（出生后 800 ms）到达 y=180，与窗口中心对应；槽年龄 20 擦除音符。
- 目标时间为窗口中心约 150 ms；窗口年龄 `[75,225)` ms 为 **Perfect，100 分**；其余 `[0,300)` ms 为 **Good，60 分**。
- 不按：**Miss**；窗口内按错键或同时触发含错音的组合：**Bad**。二者各消耗当前音符一次，计入 `miss`，连击清零。
- 每个音符最多记一次。必须释放压力后再按；持续按住不算下一次命中。没有当前目标时的按键忽略。
- 满分 4200；结束后 `n0` 保留最终分数，`n1` 保留最后的连击数。Perfect/Good/Miss/Bad 仍在 FPGA 判定并计分，但不显示判定文字或得分率。
- 乐谱中的两拍音符表示下一个音符的间隔加长；此版本是单次敲击音游，没有长按尾条判定，也没有自动伴奏。
- 开始按钮随时重开；返回按钮取消游戏；最后一个音符处理完后发送 `F0`，最多等 2 秒最终状态。

判定时钟来自 FPGA，动画时钟来自屏端定时器；实际屏幕若执行定时事件或绘图耗时导致周期明显超过 50 ms，会造成视觉位置与窗口时间有差异。分数和连击仅在快照变化时更新，避免每帧重复刷新。300 ms 宽窗口用于容纳传感器扫描和通信延迟，**仍需上板校准**。在现有配置下最短目标间隔 400 ms，判定窗口不会重叠。请先以这版验证实体屏流畅度；若需要更高速谱面、和弦、多首曲目或严格节拍同步，应改成 FPGA 主时钟驱动谱面与视觉同步协议。

## 5. 串口协议

屏幕发往 FPGA 的是裸单字节十六进制，不加 FF 结束符：

| 字节 | 行为 |
|---|---|
| `C1` | 开新局并清零分数 |
| `D0..D6` | 开放 Do/Re/Mi/Fa/Sol/La/Si 的判定窗口 |
| `F0` | 结束、保留最终成绩 |
| `A0` | 取消并返回主页 |

FPGA 发往屏幕是 ASCII 命令 `game.rx.val=<十进制数>` + `FF FF FF`。状态变化时发送，另有 250 ms 心跳；即使计数在传输中变化，下一帧仍会发送更新后的**累积值**。

状态位：0..12 分数，13..18 连击，19..24 Miss/Bad 合计，25..27 最近判定（0 Ready / 1 Perfect / 2 Good / 3 Miss / 4 Bad），28 结束标记。正常值不超过有符号 32 位整数范围。
